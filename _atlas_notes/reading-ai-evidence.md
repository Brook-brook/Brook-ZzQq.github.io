这是一份依据公开材料、经 AI 辅助整理的阅读方法练习，不代表 Brook 已复现所链接论文的实验。资料入口核对于 2026-11-12。

如果 Transformer、tokenizer 或预训练还很陌生，可先从 [Hugging Face 官方中文 LLM 课程](https://huggingface.co/learn/llm-course/zh-CN/chapter1/1)补概念，再回到一篇具体论文。课程需要一定 Python 基础，官方建议有入门深度学习背景；可先用本站 [Python 实验]({{ '/playground/python/' | relative_url }})练习变量、函数和数据处理。读完一个小节后，用自己的例子解释一个概念。

## 先确定问题 {#question}

前沿消息常把论文、模型发布、产品演示和独立测评混在一起。先写出：**谁在什么条件下，让什么系统完成什么任务？**

例如，“Agent 在实验环境里解决若干任务”，与“它能可靠处理现实中的所有工作”之间，还有环境、工具权限、错误代价和任务分布等问题。先定位论文摘要、方法和限制部分，再决定是否继续精读。

在 [arXiv 的 AI 新提交](https://arxiv.org/list/cs.AI/recent)中记录具体版本。预印本上架不表示已经通过同行评审；论文页的接收声明可继续在 [OpenReview](https://openreview.net/)或正式会议录核对。

## 再看比较条件 {#comparison}

读到“提升”时，用下面这张表拆解比较。找不到的信息也应保留为未知，不自行补齐。

| 要核对的条件 | 可写下的问题 |
| --- | --- |
| 任务与数据 | 测试集测量什么？它与准备使用的场景相似吗？ |
| 基线 | 比较的是同一模型版本、相同工具条件和合理调优后的基线吗？ |
| 计算与交互预算 | 推理 token、采样次数、工具调用、时间和人工介入是否一致？ |
| 指标与波动 | 测量的是一次成功、平均表现、最优样本，还是多次运行的分布？ |
| 复现条件 | 是否公开了代码、模型、提示与数据？许可与硬件要求是什么？ |
| 失败范围 | 哪些输入、环境、语言或任务还没有检验？ |

准确率、成功率、偏好胜率和任务完成时间衡量不同的东西。测试污染、挑选样例和过度适配都可能让分数偏离真实泛化能力；怀疑它们并不等于已经证明它们存在。

## 区分不同证据 {#evidence}

[Stanford AI Index 2026](https://hai.stanford.edu/ai-index/2026-ai-index-report)适合建立跨领域的观察坐标。使用其中图表时，继续追到原始来源、数据年份与具体评测设置。年度汇编的时间尺度，也不同于实验室今天发布的结果。

可以在阅读卡中区分四件事：

- **作者的主张**：报告写了什么，适用对象与范围是什么。
- **作者提供的证据**：实验、样本、对照和统计方法具体支持什么。
- **独立验证**：其他团队是否用相同或不同环境检查过，而非仅转述原文。
- **自己的推断**：准备把结论迁移到哪个新场景，还缺什么验证。

[NIST AI RMF](https://www.nist.gov/itl/ai-risk-management-framework)提供了风险管理视角。能力结果之外，还要问系统可能影响谁、错误代价如何，以及怎样监测与处理失败。框架、实际评估与法律合规各有边界。

## 留一份阅读卡 {#exercise}

在[观察台]({{ '/observatory/' | relative_url }})选择一份导读文档，再下载阅读计划。尝试用自己的话完成：

1. 一句话写出任务与核心主张，附具体版本和原文位置。
2. 找一个对照实验，列出双方相同与不同的预算或条件。
3. 写出一个作者没有验证、但标题容易让你联想到的场景。
4. 设计一次最小验证，并明确可能推翻自己判断的结果。

读到不懂的数学或代码时，把它缩成一个可以继续追的问题，不用一次读完全部背景。如果涉及实际 Python 数据处理，可继续进入[现有 Python 实验]({{ '/playground/python/' | relative_url }})；只有真正运行后，才记录自己的输出与观察。

更多练习可回到[学习路线与手记]({{ '/study/paths/' | relative_url }})。收藏材料与读完论文都不自动证明已经掌握。
