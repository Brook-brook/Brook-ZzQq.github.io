# 从一个能核对的小任务开始

原创、AI辅助的设计卡与公开例子，2026-11-14 Asia/Shanghai。
它不是个人学习成绩、真实模型评测或生产运行记录。

## 任务

在已有公开校园目录中，给定两个地点ID，计算平均地球半径下的代表点
球面距离，并说明来源日期、单位和目录限制。缺少ID或类型不符时拒绝
计算，不猜坐标。输出不能被解释成步行路线或建筑入口距离。

## 先分配职责

- 资料：固定公开目录，WGS84代表点，核对日2026-11-02。
- 程序/工具：验证ID与参数，用半径6371008.8m执行球面弧长计算。
- 模型（可选）：帮助理解问题和解释已经得到的结果；不代替可复算距离。
- 验收：核对具体输入、真实结果、单位和限制，不只检查“返回了文本”。

最简单基线是直接调用只读函数。这道确定计算不要求多Agent、MCP、
Skill加载或RAG。只有任务确实需要时，再加入相应层。

## 五个可在工具实验中逐步运行的输入

使用本PR编译预览中的Tool Calling实验，将JSON贴入参数编辑区，依次
校验、执行、交回。不要把源码ZIP直接当成已编译站点。

### C1：两座目录图书馆

```json
{"name":"measure_distance","arguments":{"from":"main-library","to":"medical-library"}}
```

纯工具参考约1020.225507m，可按0.001m检查计算误差。这是公式实现的
数值核对精度，不是地点资料、球面模型或现实导航的精度声明。

### C2：同一个ID

```json
{"name":"measure_distance","arguments":{"from":"main-library","to":"main-library"}}
```

参考为0m。这是合法计算，但不一定回答用户原先想比较的两个地点。

### C3：未收录的ID

```json
{"name":"measure_distance","arguments":{"from":"main-library","to":"not-in-catalog"}}
```

校验应拒绝，不执行或猜测坐标。目录未收录不等于现实中不存在。

### C4：把数值写成字符串

```json
{"name":"nearby_places","arguments":{"center":"main-library","radius_m":"200"}}
```

校验应拒绝。JSON可解析与参数类型正确是两种检查；不要静默补成数值。

### C5：在当前目录里找食堂

```json
{"name":"find_places","arguments":{"query":"食堂","category":"dining"}}
```

当前六点快照的参考是0个匹配。不能据此回答“校园没有食堂”，也不提供
食堂开放时间。来源覆盖、现实存在与字面命中是不同问题。

- 用户要解决的问题：

- 模型请求预算、工具派发预算、总截止时间分别是多少：
- 哪些内容进入模型、留在本地或被记录：
- 怎样核对任务做对，怎样记录尚未完成：
