# 第十轮：持续更新与学习沉淀

2026-11-12（Asia/Shanghai）。从远端第九轮 46dd8bf 创建 feat/atlas-iteration-10，
初始工作区干净。现有来源目录、导读、清单与隐私边界全部保留。

用户现在明确要求持续更新。本轮扩展自动元信息采集，而不是把静态目录
冒充实时信息；已整理导读和自动发现的标题继续区分。目标为约每 2 小时采集、
页面可见时每 5 分钟检查快照，并明确原站与调度延迟。

方案：

- 经实际验证的公开 RSS/Atom，仅读取标题、链接与时间，限制大小、条数、
  请求超时、源站域名与重定向，不绕过访问控制，不复制正文或生成事实摘要。
- 独立 observatory-data 分支保存按日档案、元信息修订和采集健康记录；
  出错保留旧内容。observatory-ops 分支运行 GitHub Actions 采集器，避免修改
  默认分支、生产工作流或把代码 PR 变成数据提交队列。
- 定时任务只向 ops 的触发文件提交请求，成功时保持安静；其权限不延伸到
  合并 PR、生产发布或私人数据。实际启用须以工具成功结果与首轮运行验证为准。
- 页面新增更新流、主题／源筛选、按日历史与失败／过期状态；自动标题标为
  待核对，可加入已有阅读桌。
- 原清单兼容迁移，增加本机理解手记、可恢复备份与导出；私人手记始终不进入
  自动采集、公共分支、网络请求或 URL。

不自动合并既有 PR，不修改 GitHub Pages 来源。默认分支上的 schedule 只有
合入默认分支后才会运行，因此不将开发分支中仅存在 cron 配置说成已经启用。
