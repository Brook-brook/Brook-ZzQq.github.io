## Hallmark principles applied

The workbench is the product: one current proposal, one current observation and
an explicit action. Shared tokens control every new material/type choice. Accent
marks the current step and primary action; type and real output provide hierarchy.
Use native form controls/details, local failure feedback, instant keyboard focus,
visible no-JS explanation and reduced-motion support. A finite state change may
move a few pixels; nothing moves while idle or while someone edits JSON.

## Scope and priority

1. A readable two-column execution sheet on desktop, one DOM order on phone:
   scenario, editable proposal, status/action, actual result, explanation.
2. Show the distinction between a script's proposal, application validation,
   explicit local execution, correlated observation and fixed-template prose.
   All wrong-parameter/unknown-tool/mismatched-receipt cases have useful recovery.
3. Use only the existing sourced six-point campus catalog. A result's empty list
   means no match in that catalog; a distance is a mean-radius spherical arc,
   not a route, building entrance distance or coverage claim.
4. Connect tutorial, real lab and three manual self-checks to the existing journal.
   Preserve all fifteen earlier identifiers, raw storage recovery and no visit writes.
5. Inspect actual desktop/phone, light/dark, error, result and no-JS screenshots;
   correct concrete findings, then run lint/render and a fresh-context finish review.
