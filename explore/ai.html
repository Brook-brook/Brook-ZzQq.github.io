从模型，
到会用工具的系统。

关注的不只是模型说了什么，而是系统如何选择工具、验证结果，以及在不确定时停下来。

亲手执行一次工具调用AI 与 Agent 开发学习路径阅读原理与边界

请求、工具、验证与解释

  1. 理解请求

    例如：“地图上 1,000 米，可以当作地面 1,000 米吗？”

  2. 识别前提

    需要知道 CRS、纬度、距离类型及模型假设；缺失信息不能靠猜。

  3. 执行空间工具

    在球面墨卡托演示中，用 k = 1 / cos φ 计算局部尺度。

  4. 验证与解释

    确认输入有效，并说明局部近似与球面模型的限制。

操作原有 GIS × AI 流程示意

原流程是概念示意与确定性计算，没有调用大语言模型，也不展示模型的内部思考。新增工具实验同样不调用模型，但其中的目录检索、球面距离与半径筛选会实际执行。

Tool Calling

工具调用是结构化地请求程序执行任务。参数需要验证，返回值仍需检查。

解释参数、权限与意图的区别

MCP

模型上下文协议提供连接工具与数据源的统一接口；连接并不自动保证结果正确或授予全部权限。

分清连接与授权

GIS Agent

从受约束的空间问题入手，探索可追踪的工具执行流程。当前不提供真实 Agent 服务；接入模型与外部工具仍属计划。
